# DAIC — перевірка середовища PREP-02

Дата: 28.10.2026. Статус: PREP-02 виконано; підготовчі документи збережено локальним комітом.

Основа: [MVP](daic_mvp.md), [технічні рішення](daic_technical_decisions.md), [беклог](daic_preparation_backlog.md).

## Межі кроку

- **Джерело правди:** фактичні результати локальних команд і мережевих запитів у цьому документі; вимоги залишаються в MVP.
- **Backend-контракт:** без змін — стан вікна, трея й позиції належить головному процесу Electron; зовнішнього API немає.
- **Done:** вибрано точні версії локальних інструментів, перевірено registry, офіційне джерело Electron і доступ на запис без адміністратора; визначено безпечний порядок генерації, документи збережено локальним комітом.
- **Не робимо:** встановлення/оновлення софту, генерацію каркаса, прикладний код, UI та повне завантаження Electron.

## 1. Зафіксоване середовище

| Компонент | Обрана версія / значення | Фактична перевірка |
| --- | --- | --- |
| Node.js | `24.20.0`, гілка 24 LTS | `node --version` → `v24.20.0` |
| npm | `11.19.0` | `npm.cmd --version` → `11.19.0` |
| Git | `2.56.0.windows.2` | `git --version` |
| Node platform / arch | `win32` / `x64` | `node -p "JSON.stringify({arch:process.arch,platform:process.platform})"` |
| Робочий каталог | `L:\daic` | Git і перевірки запису виконані з цього каталогу |

Для першого каркаса залишаємо вже встановлені Node.js `24.20.0` і npm `11.19.0`. Це зафіксована відтворювана база, а не твердження про найновіший patch. Оновлення системного Node не потрібне для проходження перевірених нижче мінімальних вимог. Якщо перевірка решти пакетів у PREP-03 виявить вищу вимогу, зміну версії треба записати явно.

У майбутньому README вказати ці точні версії та використовувати `npm.cmd`/`npx.cmd` у PowerShell. Системну Execution Policy не змінювали.

## 2. npm registry і базові вимоги

Команди виконано з явним registry `https://registry.npmjs.org/`:

```powershell
npm.cmd ping --registry=https://registry.npmjs.org/
npm.cmd view @electron-forge/cli version engines --json --registry=https://registry.npmjs.org/
npm.cmd view electron dist-tags.latest --json --registry=https://registry.npmjs.org/
npm.cmd view npm@11.19.0 engines --json --registry=https://registry.npmjs.org/
```

| Перевірка | Результат |
| --- | --- |
| npm ping | `PONG`, 360 ms |
| Поточний Forge CLI у registry | `8.0.1`, `engines.node: >= 22.13.0` |
| Вимога npm `11.19.0` | `^20.17.0 || >=22.9.0` |
| Встановлений Node `24.20.0` | Відповідає обом перевіреним вимогам |
| Поточний Electron `latest` у registry | `45.1.0` |

Ці відповіді є знімком metadata, не вибором остаточного набору залежностей. Forge `8.0.1` і Electron `45.1.0` ще не перевірялися разом із шаблоном, TypeScript, Webpack і maker. Остаточний вибір та сумісність належать PREP-03.

## 3. Офіційні завантаження Electron

Виконано HTTPS-запити через Windows PowerShell зі стандартною перевіркою TLS:

- GET `https://github.com/electron/electron/releases/download/v45.1.0/SHASUMS256.txt` → **HTTP 200**; відповідь прочитана.
- У списку є `electron-v45.1.0-win32-x64.zip` із SHA-256 `55eaba17abff7b5bba6c3bbc85068967379024fe742fe9c7fdba9118922ccbe2`.
- HEAD `https://github.com/electron/electron/releases/download/v45.1.0/electron-v45.1.0-win32-x64.zip` → **HTTP 200**, `Content-Length: 158224448`.

Перший пошук рядка не врахував формат відповіді та маркер `*` перед назвою файла в SHASUMS. Після декодування відповіді й виправлення пошуку запис знайдено. Це була помилка перевірки, а не відсутній артефакт.

Мережевий шлях до metadata і Windows x64 архіву доступний. Повний архів не завантажувався, його SHA-256 локально не обчислювався, npm postinstall Electron не запускався. Фактичне встановлення Electron перевіряється при створенні каркаса.

## 4. Права запису

У кожному каталозі створено унікальний файл `daic-prep02-<GUID>.tmp`, записано рядок, прочитано його й перевірено повний збіг. У `finally` видалено тільки створений файл.

| Каталог | Запис → читання → видалення |
| --- | --- |
| `L:\daic` | Пройдено |
| `C:\Users\uasky\AppData\Roaming` | Пройдено |

Перевірка виконана з `Elevated=False`: Windows-права адміністратора не використовувалися. Дозвіл на вихід із sandbox інструмента не означає підвищення прав Windows.

Робочий каталог і батьківський каталог майбутнього `<appData>/DAIC` доступні для запису. Сам каталог `DAIC` та файл `settings.json` поки не створювалися; перевірка запису саме через Electron API залишається для головного процесу.

## 5. Безпечний порядок створення каркаса

1. Підготовчі документи зберегти локальним комітом. Не включати сторонні зміни й не виконувати push у цьому кроці.
2. У PREP-03 визначити точну версію `create-electron-app` і сумісні версії пакетів.
3. Перед генерацією повторно перевірити `git status`; нові зміни зберегти окремо, не видаляти й не перезаписувати.
4. Генерувати `webpack-typescript` у новій унікальній тимчасовій папці, а не безпосередньо поверх репозиторію.
5. Перевірити отримані конфігурації й список файлів. Перенести в `L:\daic` тільки файли каркаса; `.git/`, `Tasks/` і наявні документи не замінювати. Вкладений `.git/` генератора не переносити.
6. Lockfile має відповідати фінальному `package.json`. Після перенесення перевірити чисте встановлення через `npm.cmd ci`, запуск, typecheck, package і make.

Генератор у цьому кроці не запускався. Команда з конкретною версією буде записана після PREP-03.

## 6. Статус і наступний крок

Мережеві та файлові перевірки пройдено. Документи PREP-01, беклог і цей протокол збережено локальним комітом `Document MVP preparation and verify local environment`. GitHub-публікація не виконувалася.

Після коміту Git не показав незбережених змін у відстежуваних файлах, але виявив нову невідстежувану папку `img/`. Її не змінювали й не включали до коміту. Перед генерацією каркаса потрібно окремо врахувати та зберегти її вміст; поточний робочий стан не називаємо повністю чистим.

Наступний крок — **PREP-03: точні версії та специфікація каркаса**. Загальна сумісність ще не доведена, готовність MVP не заявляється.

**Перезбірка:** не потрібна. **Перезапуск:** не потрібний. **Перевірено фактично:** npm registry, metadata пакетів, GET контрольних сум Electron, HEAD архіву, запис/читання/видалення тимчасових файлів без адміністратора. **Після створення каркаса перевірити:** повне встановлення залежностей і фактичний запуск Electron.
