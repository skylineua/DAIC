# ТЗ: MVP десктопного персонажа «Ї» для Windows

## Мета

Створити невеликий локальний Windows-застосунок, який показує блакитного кристального персонажа «Ї» поверх інших вікон.

У першій версії персонаж статичний. Його можна перетягувати мишею, приховувати, повертати на екран і закривати через системний трей.

Це завершений мінімальний desktop-застосунок без підключення до ШІ.

## Межі MVP

Реалізувати:

- прозоре вікно без рамки та заголовка;
- відображення одного PNG персонажа;
- режим поверх звичайних вікон;
- перетягування персонажа мишею;
- збереження та відновлення позиції;
- меню в системному треї;
- встановлення й запуск на Windows.

У цій ітерації не реалізовувати:

- підключення до Codex, Kiro Crew або інших AI-сервісів;
- читання екрана, файлів, буфера обміну чи активного вікна;
- інтеграцію з VS Code;
- чат, бульбашки, повідомлення та голос;
- анімації, розкадровку, зміну емоцій;
- справжній 3D, фізику скла або заломлення світла;
- автозапуск, автоматичне оновлення, телеметрію;
- окремий екран налаштувань;
- підтримку інших операційних систем.

## Технології

Використати:

- Electron;
- TypeScript;
- звичайні HTML і CSS для відображення;
- Electron Forge для розробки та пакування;
- локальний JSON для збереження позиції.

React, Canvas, WebGL, базу даних і окремий HTTP-сервер не додавати: для статичного зображення вони не потрібні.

Використовувати стабільні сумісні версії залежностей та зафіксувати їх у lockfile.

## Джерело правди та структура

Перед початком реалізації зафіксувати:

1. **Джерело правди:** головний процес Electron керує життєвим циклом вікна, видимістю та збереженою позицією.
2. **Внутрішній контракт:** renderer відображає персонажа; головний процес керує вікном і треєм. Не створювати зовнішній API.
3. **Критерій done:** застосунок пройшов ручні сценарії з розділу «Приймання».
4. **Виключений обсяг:** усе, що перелічено в межах MVP як відкладене.

Пропонована структура:

- `src/main/` — вікно, трей, налаштування;
- `src/renderer/` — сторінка з персонажем;
- `assets/yi.png` — персонаж;
- `assets/tray.ico` — іконка трея;
- `README.md` — запуск, збірка, ручна перевірка.

Не ускладнювати структуру додатковими абстракціями без потреби.

## Графічний ресурс

Використати погоджений образ: блакитна кристальна «Ї» з двома очима-крапками.

Вимоги до `assets/yi.png`:

- справжня прозорість alpha;
- один персонаж у спокійному стані;
- без фону, підлоги, підписів і рамки;
- персонаж повністю вміщується в зображенні;
- мінімальні прозорі поля;
- без чорного, білого або кольорового ореолу на краях;
- бажана висота вихідного зображення — щонайменше 512 px.

Показувати персонажа приблизно 128 логічних пікселів заввишки зі збереженням пропорцій.

Якщо готового PNG немає, не видавати референсний аркуш із кількома станами за фінальний ресурс. Винести шлях і розмір зображення в одну конфігурацію, щоб ресурс можна було замінити без зміни логіки.

## Поведінка вікна

- Вікно прозоре, без стандартної рамки й заголовка.
- Не показувати HTML-підкладку, смуги прокручування або елементи браузера.
- Розмір вікна близький до габаритів персонажа; не створювати повноекранний прозорий шар.
- Вікно залишається поверх звичайних вікон VS Code, браузера й Провідника.
- Не вимагати прав адміністратора.
- Не показувати окрему кнопку персонажа на панелі задач.
- При запуску не перехоплювати клавіатурний фокус.
- Персонаж не реагує на наведення, одиночний або подвійний клік додатковими діями.
- Ліва кнопка миші використовується для перетягування.

Не вимагати роботи поверх екрана UAC, екрана блокування чи ексклюзивного повноекранного режиму.

Точне пропускання кліків за alpha-силуетом не входить у MVP. Прозорі поля мають бути мінімальними; усе поза невеликим вікном персонажа повинно залишатися доступним для роботи.

## Позиція та монітори

При першому запуску:

- розмістити персонажа в нижньому правому кутку робочої області основного монітора;
- відступити приблизно 24 логічних пікселі від країв;
- врахувати панель задач.

Після перетягування зберігати позицію у файлі в каталозі `app.getPath('userData')`.

На наступному запуску відновлювати її.

Якщо попередній монітор від’єднали або збережена позиція недоступна, повернути персонажа у видиму робочу область.

Відсутній або пошкоджений файл налаштувань не повинен блокувати запуск: використати стандартну позицію.

## Системний трей

Іконка в треї присутня протягом роботи застосунку.

Меню:

- «Приховати Ї» / «Показати Ї» — залежно від поточного стану;
- «Повернути на основний екран»;
- «Вийти».

Приховування не завершує процес.

«Вийти» завершує застосунок повністю.

Повторний запуск застосунку не створює другого персонажа: активувати наявний екземпляр і показати його, якщо він прихований.

## Порядок реалізації

Виконувати послідовно, окремими кроками:

1. Головний процес: запуск одного екземпляра, вікно, трей, збереження позиції.
2. Відображення PNG: прозорість, розмір, перетягування.
3. Пакування та ручне приймання.

Після кожного кроку вказувати:

- що реалізовано;
- чи потрібно перезібрати;
- чи потрібно перезапустити;
- який сценарій перевірити.

## Приймання

Збірка без помилок сама по собі не означає завершення.

Перевірити вручну:

1. Запустити застосунок — видно одного персонажа без рамки й фону.
2. Відкрити VS Code, браузер і Провідник — персонаж залишається поверх них.
3. Надрукувати текст у редакторі — персонаж не перехоплює фокус.
4. Перетягнути його в інше місце — рух працює без стрибків.
5. Закрити й запустити застосунок — позиція відновилася.
6. Приховати й показати персонажа через трей.
7. Виконати «Повернути на основний екран» — персонаж повернувся у видиму область.
8. Запустити застосунок повторно — другого екземпляра немає.
9. Перевірити краї PNG на світлому та темному фоні.
10. Перевірити масштабування Windows 100%, 125% і 150%, наскільки дозволяє середовище.
11. Виконати «Вийти» — персонаж та іконка трея зникли, процес завершився.
12. Встановити зібраний пакет і перевірити запуск установленої версії.

Для кількох моніторів додатково перевірити відновлення після зміни конфігурації. Якщо обладнання недоступне, явно позначити цей сценарій як неперевірений.

## Результат

Надати:

- вихідний проєкт;
- Windows-інсталятор;
- короткий README із командами запуску та збірки;
- список фактично виконаних перевірок;
- відомі обмеження й неперевірені сценарії.

Не позначати задачу завершеною, якщо перевірено лише запуск у режимі розробки, а встановлена версія не перевірена.
