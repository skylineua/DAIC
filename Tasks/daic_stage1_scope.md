# Перший етап реалізації DAIC

Джерело правди: головний процес володіє вікном і видимістю; Electron bounds — поточна позиція; `%APPDATA%/DAIC/settings.json` — збережений знімок `{version:1,position:{x,y}}` у DIP.

Контракт: renderer показує лише статичний PNG. Main передає геометрію компонування через параметри локального URL під час завантаження. Renderer не має Node, IPC, preload чи доступу до налаштувань. Штатна drag region рухає вікно, main отримує події move.

Done: тести налаштувань/геометрії, запуск реального Electron, перевірки відображення, drag, повторного запуску, persistence й трея з фактичними результатами. Недоступні ручні перевірки залишаються явно not tested.

Не додаємо: анімацію, ШІ, інтеграції, додаткові стани, діалоги, автозапуск, автооновлення, сервер або БД. source-файли не редагуємо.

Уточнення PREP-03: для цього етапу tsc компілює TypeScript, простий build-скрипт копіює renderer і незмінний PNG, Forge пакує. Webpack, loaders та dev server не потрібні. Це явне спрощення інструментів; логічний контракт PREP-04 зберігається. Трей використовує nativeImage із того самого PNG; фінальний ICO та інсталятор не є критерієм цього етапу.

Порядок: спочатку SettingsService, PositionService, розрахунок alpha bounds і їх тести; потім WindowService/TrayService та renderer; потім реальні перевірки.
